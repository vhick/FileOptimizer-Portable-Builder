# v1.3 — FileOptimizer 18.00.2889 icon export fix

## Failure reproduced from the supplied GitHub log

- Build selected official release `18.00.2889`.
- Official SourceForge download completed; local calculated SHA-256 was logged.
- `7z t` reported `Everything is Ok` and all files were extracted.
- `scripts/build.ps1:160` invoked `Extract-OfficialIcon.ps1` and failed with `Missing icon resource type 14`.
- GitHub never reached launcher compilation or packaging.

## Changes

- Handle string and integer Windows icon-resource names correctly; never retain a transient native pointer.
- Try each vendor icon group, with clear diagnostic messages.
- Optional fallback to upstream `FileOptimizer32.exe` icon if 64-bit has none; never use generic icons.
- Add icon smoke test before the large download on the Windows runner.
- Update known fallback release to the confirmed official `18.00.2889`.
- Fix malformed final `Write-Host` line in `scripts/build.ps1`.
- Leave the original v1.2 TraceGuard launcher sources and portable layout unchanged.

## Verification and limitations

The offline Python static/unit tests pass, including assertions for the corrected native resource handling. This environment cannot run Windows PowerShell or compile a Windows executable, so the patch **has not yet been run successfully in GitHub Actions**. The new workflow smoke test verifies that the extractor can process icon resources from the Windows OS before downloading the vendor archive; a successful end-to-end GitHub Actions job and Windows runtime test are still required.

The SourceForge checksum listing was blocked by 403 in the supplied run. Archive integrity is not the same as independent publisher SHA-256 verification. Add a publisher-verified `expected_sha256` when available.
